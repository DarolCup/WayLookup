# Разработка и сообщения об ошибках

Проект находится на ранней стадии. Начните с README и [описания архитектуры](docs/architecture.md). Интерфейс сейчас на русском. Предложения по другим языкам, качеству OCR и совместимости с мониторами приветствуются.

## Локальная проверка

Для ядра достаточно Python 3.11+. Для интерфейса нужны Arch-зависимости из README.

```bash
python -m unittest discover -s tests -v
uvx ruff check .
python -m build
```

GUI проверяется отдельно, в настоящей Wayland-сессии:

```bash
python tests/live_smoke.py
```

Этот тест временно перекрывает текущий монитор. Он использует отдельные настройки, синтетическую сцену и локальный сервер перевода. Не запускайте его посреди сетевого матча или другого действия, требующего непрерывного ввода.

## Что приложить к сообщению об ошибке

- Шаги воспроизведения, ожидаемый и фактический результат.
- Версии WayLookup, Python и Hyprland, масштаб и число мониторов.
- Вывод `waylookup doctor` (или `python -m waylookup doctor` из папки проекта).
- Язык OCR, PSM и провайдер перевода; текст ошибки из карточки.
- По возможности — небольшой пример текста или обезличенный скриншот.

Не прикладывайте API-ключи, личные файлы `words.txt`, содержимое приватных окон или словари с неразрешённым распространением. Не требуются полные переменные окружения и дампы всей сессии.

## Изменения

Описывайте конкретную проблему и новое поведение. Проверяйте затронутый сценарий. Для исправлений парсинга или асинхронного состояния добавляйте регрессионный пример. Для визуальных изменений приложите скриншот на синтетической сцене.

## Подготовка и публикация релиза

Только сопровождающий с доступом к GitHub выполняет публикацию. Сначала закоммитьте изменения. Версии в `pyproject.toml`, `waylookup/__init__.py` и `packaging/PKGBUILD` должны совпадать.

```bash
# Только подготовка файлов в release/vVERSION/, GitHub не меняется:
python scripts/publish.py

# После установки github-cli и обычного gh auth login:
python scripts/publish.py --publish
```

Скрипт проверяет тесты, собирает Arch-пакет и wheel из одного коммита, создаёт архив исходников, SHA256SUMS и SOURCE-COMMIT.txt. В режиме `--publish` он создаёт публичный `DarolCup/WayLookup`, отправляет историю в `main` и публикует релиз с файлами. Можно передать другое `--repo OWNER/REPO`; README-ссылки тогда нужно обновить. Токены в скрипт не записываются, настройки Git-авторизации не меняются, force-push не используется. Существующий релиз и несвязанная история не перезаписываются.
